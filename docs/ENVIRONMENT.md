## Gotchas by tool

* Recipe-language gotchas learned: a triple-quoted string followed by `+ NAME + """` on its closing line does not parse ("expected a value but found an indent"): give each piece a name and add the names. Also: no `**kwargs`, `asset` is a reserved built-in name, node parameters named `class` are fine as kwargs. When patching Rust or recipes from the shell never use perl `s|..\|..|` (an escaped delimiter turns into an alternation and silently inserts text at the top of the file: it happened three times); use the Edit tool or index/substr scripts, and write multi-line code with the Write tool, not heredocs with quotes.
* GDScript/Godot gotchas learned: a Packed array stored in a Dictionary is copied by a cast (use a plain Array for grids); comments are `#` not `//`; `await physics_frame` several times before using the navigation map, and `NavigationServer3D.map_get_closest_point` returned nothing for a baked mesh here, so reach is tested geometrically; Godot's `get_rendering_info` primitives count includes shadow passes; vsync must be switched off to measure frame rate; a regex with backslashes is mangled by the Bash tool (use string functions).
* GDScript/Godot, learned on the creek world: Godot 4.7 imports a node with `EXT_mesh_gpu_instancing` as ONE mesh (the bridge builds the MultiMesh from the accessors); `GLTFState.get_scene_node` ids are stale after the importer swaps its mesh nodes (find nodes by name); removing a child of a parent with 60 000 children is linear (group nodes under parents); one navigation bake holds about 65 000 vertices and returns NOTHING above that, with no error (bake in tiles); a bake filter box "from minus to plus 100 km" puts every vertex at a garbage height (make it as tall as the ground).
* Blender/Cycles, learned on the creek world: a procedural volume is marched in steps of a tenth of its box (haze is nested constant boxes, mist one marched box); a constant slab's lid shows as a line when a camera stands at its height; scanned plants are opaque and render as black card against the sun without `foliage_translucency`; a bake writes into the ACTIVE image node of every material slot of the object (other slots get a throwaway target).
* Tooling gotchas: in Bash tool commands, double backslashes get collapsed (write Rust files with the Write/Edit tools, not
  heredocs, when they contain `\\` or `\u{..}`); multi-line `sed` rewrites by line number are fragile (re-read first). Patch scripts: perl `q{...}` needs balanced braces (three scripts died on a stray `}`), so use heredoc strings inside a script file written with the Write tool, or the Edit tool. Never build while `pt` is running: the build cannot replace `pt.exe` (use `cargo check`, or `cargo test -p pt-core`).

* Bench and corpus: `cargo test` and `cargo build` cannot replace `pt.exe` while a bench is running (wait, or use another target dir). The tool server the editor starts from `.mcp.json` (`pt.exe mcp --ui 7700`) holds the file open in the same way: the build then ends with "failed to remove file" and the old program keeps running, so a check that "found nothing" may be the old check; rename the running file (`mv target/release/pt.exe target/release/pt_running_server.exe`) and build again. `merge` takes at most 4 inputs. In hcs write tunable numbers with a decimal point and structure (counts, quarter turns) as whole numbers. Never name a bench run like the folder that holds hand-written sources (the first version overwrote them; output now goes to `corpus/recipes/tuned/`). A full 50-asset baseline run takes about 8 minutes. Quaternius is excluded (licence changed, see `corpus/SOURCES.md`).

* Technique notes from third-party tutorials (transcripts only, outside the repo): [TECHNIQUE_NOTES.md](TECHNIQUE_NOTES.md). `yt-dlp` is installed (winget); fetch subtitles only with `--skip-download --write-auto-subs --sub-langs en`, a full playlist at once triggers HTTP 429, so pause and retry the missing videos.

* Lessons moved here from the owner's memory notes (2026-10-12): a Blender WORLD volume blacks out the frame (fog is a bounded box); relative render output paths are silently lost (always absolute); `sun_direction` is not readable headless (calibrated: sun_rotation = 90 + azimuth in Proteus coordinates); PowerShell 5.1 writes a BOM that `serde_json` rejects (write with `[IO.File]::WriteAllText` and `UTF8Encoding($false)`) and `Get-Content -Raw` strings serialize wrongly through `ConvertTo-Json` (use `[IO.File]::ReadAllText`); style fallback colours are LINEAR; AgX shifts greens to cyan and highlights to pink (use Khronos PBR Neutral); Poly Haven `rock_boulder_cracked` is salmon (use a per-channel tint); hydraulic erosion above about 600k droplets destroys the analytic terrain; a stalled Godot process blocks the scorecard because `run_godot` has no timeout (a fix is queued in STATUS); when a delivery measure regresses on a bigger world, check whether the metric followed the world before blaming the world (4 of 6 regressions in scorecard v3 were metrics).

## Keeping the owner's PC usable

The owner works on this PC (16 GB of memory, one 8 GB GPU) while jobs run. `pt` starts Blender, Godot, the glTF validator and the judge server through `pt_cli::lowload`: below-normal priority, killed when `pt` exits, and (all but the judge server) a job memory cap of `PT_HEAVY_MEM_GB` (default 8; 0 removes it); Blender gets all cores but two (`PT_HEAVY_THREADS`). The terrain bake (`pt scorecard --bake`, about 10 GB on the creek world) and the vision judge (`--judge`, 6.5 to 7.7 GB of the GPU) are opt-in. Say in one line before any job that will take minutes of heavy memory or GPU, and never leave one running when wrapping up.

## Look-development renders of the creek world (2026-10-12)

The creek world holds about 9.5 million triangles over 50 unique meshes and 10 000 objects; a one-camera Cycles render needs about 4.3 GB in Blender before the GPU copy, and the driver's own host allocations count against the job cap: at the default 8 GB cap the render stopped (first "out of GPU and shared host memory", after the scene shrank "out of GPU memory" at only 2.1 GB of the card). What works: the lighter recipe `out/preview/cascade_preview.hcs` (a quarter of the scan triangle caps, thinner grass tiles, identical placement), `--only CAMERA --cull 60` (drops instances, far stand-ins and terrain cells outside the view; the far terrain level stays whole), and `PT_HEAVY_MEM_GB=10` for that one job (still a hard cap, still low priority; peak about 9 GB, minutes). Measure with `out/lookdev/inspect_blend.py`-style probes (objects, unique meshes, vertices, image bytes) before guessing.
