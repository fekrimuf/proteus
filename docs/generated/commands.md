# Registered commands

Generated by `pt status --write` from `crates/pt-cli/src/registry.rs`. Do not edit by hand; `pt docs-check` fails when it is stale.

Every command below is on the command line and, under the tool name, in the agent's tool list. A heavy command takes the machine (GPU or several GB of memory) and runs at low priority under a memory cap; it needs no permission, one at a time.

|---|---|---|---|
| `docs-check` | `docs_check` |  | Check the documentation: size budgets, broken links, banned headings, mangled Windows paths, the STATUS date, the index, and that the generated state and command table are current. Exit 1 on any problem. |
| `edit` | `edit` |  | Record the owner's decision about one placed object in an edits file, by its stable id (from `pick`): remove it, move it by (dx dy dz) or to a place (with `to`), scale it, or add a new one. The decision is replayed on every rebuild of the world. |
| `gate` | `gate` | yes | The checks every commit must pass, in order: build, lint (the platform-independent maths rule and the ban on crash-prone shortcuts, enforced by clippy on all production code), the documentation harness, and the tests. Stops at the first failing step and names it. Takes minutes: it builds and tests the workspace. |
| `ground-check` | `ground_check` |  | Cook a world on the CPU (no render, no GPU) and list, per scene camera, the objects that float, hang over a slope or bank, are mostly under water (flat lids) or are buried. With frames and annotate it writes ground_<camera>.png with each one boxed (red float, orange hanging, yellow shallow, magenta buried). Fails when anything floats or hangs inside a camera view. |
| `recipes` | `recipes` |  | Build every recipe in recipes/, check its specs and its static flow check, and compare each content hash with recipes/golden.json. Exit 1 when any recipe fails. After an intended numeric change, --update re-records the hashes (then also run `pt gym-baseline`). |

| `survey` | `survey` | yes | Look at a world from many sides in seconds, in the game engine instead of the offline renderer: a walk (standing points with four views each), the area from above, the scene's cameras, and a close-up pair of every object the ground check flags (floating, hanging, mostly under water), all in one engine launch, written as contact sheets of twelve labelled views. ## Usage

### docs-check

`pt docs-check`


### edit

`pt edit <file> <scope> [id] <op> [numbers...] [--to]`

* `file` (required): edits .json file to write (for example edits/cascade.json)
* `scope` (required): name of the scatter the object belongs to (the scope its recipe passes to edits_of)
* `id`: the object's stable id (the `pid` that `pick` reports); leave out for `add`
* `op` (required): remove | move | scale | add
* `numbers`: move: dx dy dz; scale: one factor; add: x y z [pscale]
* `--to`: with move: the numbers are a place in the world, not an offset

### gate

`pt gate [--quick] [--only ONLY]`

* `--quick`: leave out the tests (build, lint and docs only)
* `--only`: run only these steps, comma-separated: build, lint, docs, tests

### ground-check

`pt ground-check <recipe> <scene> [--radius RADIUS] [--frames FRAMES] [--annotate ANNOTATE] [--lookdev]`

* `recipe` (required): the world's recipe .hcs file
* `scene` (required): the scene .json file that holds the cameras
* `--radius`: metres around a camera that count as in view (default 45)
* `--frames`: folder holding the rendered frames to draw on
* `--annotate`: folder to write the annotated frames to
* `--lookdev`: cook in the look-development tier (the tier the frame was rendered in)

### recipes

`pt recipes [--update]`

* `--update`: re-record recipes/golden.json from this run

### render-scene

`pt render-scene <input> <scene> <out> [--quick] [--samples SAMPLES] [--keep KEEP] [--lod] [--only ONLY] [--cull CULL] [--lookdev] [--fresh]`

* `input` (required): recipe .hcs or a .glb file
* `scene` (required): scene .json file (cameras, lighting, render settings)
* `out` (required): output .png path (the report names every frame written)
* `--quick`: quarter samples and half size
* `--samples`: Cycles samples
* `--keep`: folder to keep the exported world and the Blender files in
* `--lod`: render with the levels of detail an engine would get
* `--only`: render only these cameras (comma-separated names)
* `--cull`: with only: drop what the chosen cameras cannot see beyond this many metres
* `--lookdev`: the look-development tier: fits this machine, not the full-quality world
* `--fresh`: ignore the cache of the cooked world

### review-tiles

`pt review-tiles <frame> <out_dir>`

* `frame` (required): the rendered frame (.png)
* `out_dir` (required): folder to write tile_r1c1.png ... tile_r2c3.png to

### scorecard

`pt scorecard <recipe> <scene> --out OUT [--no-render] [--no-fps] [--no-lod] [--quick] [--samples SAMPLES] [--notes NOTES] [--reuse] [--bake] [--judge] [--brief BRIEF] [--foil FOIL] [--baseline BASELINE]`

* `recipe` (required): the world's recipe .hcs file
* `scene` (required): the scene .json file
* `--out` (required): folder for the report, frames and exports
* `--no-render`: skip the Blender render (export only)
* `--no-fps`: skip the Godot frame-rate and walkability rows
* `--no-lod`: export the engine file without levels of detail
* `--quick`: quarter samples and half size
* `--samples`: Cycles samples
* `--notes`: text to store in the report
* `--reuse`: keep the stages an earlier, cut-off run already finished in out
* `--bake`: bake the layered terrain materials to textures for the engine file (takes several GB of memory)
* `--judge`: ask the local vision judge about the frames (takes the whole GPU)
* `--brief`: the brief the judge scores brief fit against (default: the scene's own)
* `--foil`: a different brief to test the judge against (repeatable)
* `--baseline`: an earlier scorecard.json to compare against

### status

`pt status [--write]`

* `--write`: store the state and the command table under docs/generated/

### survey

`pt survey <recipe> <scene> [--out OUT] [--at AT] [--radius RADIUS] [--stations STATIONS] [--closeups CLOSEUPS] [--passes PASSES] [--size SIZE] [--lookdev] [--plan-only]`

* `recipe` (required): the world's recipe .hcs file
* `scene` (required): the scene .json file (cameras, style)
* `--out`: folder for the pictures, the sheets and the report (default out/survey/<recipe name>)
* `--at`: middle of the area to look at, as X,Z in metres (default: where the scene's standing cameras are)
* `--radius`: radius of that area in metres (default: the cameras' spread plus 40, at least 60)
* `--stations`: standing points of the walk, four views each (default 6)
* `--closeups`: flagged objects to look at from two sides each (default 12)
* `--passes`: pictures per view, comma-separated: lit, flags, kinds (default lit,flags)
* `--size`: picture size as WIDTHxHEIGHT (default 1280x720)
* `--lookdev`: cook in the look-development tier
* `--plan-only`: plan the views and write the plan and survey.scene.json without starting the engine

### walk

`pt walk <recipe> <scene> [--out OUT] [--size SIZE] [--lookdev] [--check]`

* `recipe` (required): the world's recipe .hcs file
* `scene` (required): the scene .json file (cameras, style)
* `--out`: folder for the engine file, the notes and their pictures (default out/walk/<recipe name>)
* `--size`: window size as WIDTHxHEIGHT (default 1600x900)
* `--lookdev`: cook in the look-development tier
* `--check`: nobody at the keyboard: open the window, note what is in the middle of the first camera's view, and close (proves the walk-through works on this machine)

### world

`pt world <manifest> <action> [args...] [--variant VARIANT] [--quick] [--samples SAMPLES] [--keep KEEP] [--lod] [--only ONLY] [--cull CULL] [--lookdev] [--fresh] [--radius RADIUS] [--frames FRAMES] [--annotate ANNOTATE] [--frame FRAME] [--size SIZE] [--also ALSO]`

* `manifest` (required): the world file (for example worlds/cascade.world.json)
* `action` (required): info | scene | render | check | pick
* `args`: render: OUT.png; pick: CAMERA X Y
* `--variant`: which variant to expand (default: the world's default)
* `--quick`: render: quarter samples and half size
* `--samples`: render: Cycles samples
* `--keep`: render: folder to keep the exported world in
* `--lod`: render: render with the levels of detail an engine would get
* `--only`: render: only these cameras (comma-separated)
* `--cull`: render: with only, drop what the cameras cannot see beyond this many metres
* `--lookdev`: render, check, pick: the look-development tier
* `--fresh`: render: ignore the cache of the cooked world
* `--radius`: check: metres that count as in view; pick: a pixel radius for a region
* `--frames`: check: folder of rendered frames to draw on
* `--annotate`: check: folder for the annotated frames; pick: the annotated output .png
* `--frame`: pick: the rendered frame .png the pixel refers to
* `--size`: pick: WIDTHxHEIGHT of the picture the pixel refers to
* `--also`: pick: more pixels as X,Y (repeatable)
