# Sharpening five bets before the kernel hardens

The five bets in PLAN.md are sound in direction and mostly supported by prior art, but five claims are overstated, three gates are unsupported as worded, and the largest threat is legal rather than technical. The compiler-with-autodiff core (Bet 1) follows the proven Warp/DiffTaichi/Slang pattern, and no off-the-shelf Rust option can differentiate runtime-compiled user snippets, so the plan's decision to write its own IR is correct. The content-addressed runtime (Bet 3) is well grounded in Bazel, Salsa and Nix, but "identical hashes on another machine" is achievable only for a declared CPU reference class that owns its math library. It is not achievable for GPUs. The agent bet (Bet 4) is the weakest as framed. MCP-over-Houdini is no longer unique, since SideFX and NVIDIA previewed an official MCP server for Houdini 22. A custom `hcs` language also faces a cold-start problem that no study has measured. Differentiable inverse design (Bet 5) is well supported for fixed-structure fits and thinly supported for the Phase 5 and 6 gates. The most serious risk is the SideFX EULA, which bars using Houdini to build a competing product and therefore contradicts the plan's "parity checks against observable Houdini behavior." This report is research synthesis, not legal advice. Evidence gaps are flagged inline and collected at the end.

## Prior art validates the store design but not the rhetoric against Houdini

The plan's columnar copy-on-write store has a direct production precedent. Blender introduced implicit sharing in 3.6 to avoid copying large chunks, but it works only when domain sizes and types match, and a Mesh to Curve bug (#110485) crashed because of incorrect sharing ([PR 106917](https://projects.blender.org/blender/blender/pulls/106917), [commit](https://demo.gitea.com/bartvdbraak/blender/commit/803589ca5a3ff6bfc60740ef841f98ba93cc55ba)). Blender's own release notes claim "at least 25%" memory improvement in simple cases ([3.6 notes](https://developer.blender.org/docs/release_notes/3.6/nodes_physics/)), which is the only public number found. PLAN's "order of magnitude" is therefore a hypothesis for the Phase 1 gate to prove, not a fact. Blender's fields are immutable DAGs evaluated lazily on demand ([Blender dev docs](https://developer.blender.org/docs/features/nodes/fields/)), which supports the fusion bet. Blender 5.0 added bundles, closures and volume grids ([5.0 notes](https://developer.blender.org/docs/release_notes/5.0/geometry_nodes/)), so multi-representation geometry is a multi-year effort even for a mature team, and closures (higher-order graph abstraction) deserve a design slot next to subnets and HDAs.

Several statements about Houdini are overstated. Packed primitives are mature: they copy references rather than geometry, support delayed-load disk references and viewport instancing, though instances of disk or memory packed prims cannot carry per-instance attributes except `material` and `vel` ([SideFX packed docs](https://www.sidefx.com/docs/houdini/model/packed.html)). "An opt-in afterthought" is rhetoric. "Houdini runs each node as a separate full pass with a full copy" has no source: the HDK stores attributes in paged arrays ([HDK GA](https://www.sidefx.com/docs/hdk/_h_d_k__g_a__using.html)) and Houdini tracks data IDs for cache optimizations ([hou.Geometry](https://www.sidefx.com/docs/houdini/hom/hou/Geometry.html)), so internal sharing may exist, and the notes could not confirm or refute it. "Cooking is serial" is also doubtful: PDG distributes work, and Solaris layers are diffable text. Houdini 22 ships native Gaussian splats (train, relight, Karma render) ([CGChannel](https://www.cgchannel.com/tag/relight-gaussian-splat/)), so splats are not a differentiator; one container with cross-conversion is. The defensible differentiation is that instance tables and shared columns are uniform defaults, and that keys are content-addressed across machines, where PDG caching is file-path and timestamp based ([work item cache state](https://www.sidefx.com/docs/houdini/tops/pdg/workItemCacheState.html)). A ten-minute Houdini micro-benchmark would settle the copy question, but running Houdini conflicts with the clean-room finding below, so it should be done by a non-contributor or skipped.

On open-source competition, no full agent-native Houdini replacement was found. The only Rust node-based 3D modeler located was Blackjack, whose README promises no stability ([Blackjack](https://github.com/Shchvova/blackjack)). Fidget, a Rust SDF tape compiler with JIT and interpreter fallback and interval-arithmetic simplification ([Fidget](https://github.com/mkeeter/fidget)), is the closest prior art for the plan's implicit-field representation and reference-interpreter design. Gaffer's hash-before-compute design, the nearest analogue to the CAS bet, was not retrieved.

## The IR and autodiff plan matches proven designs if four rules are added

Warp, DiffTaichi and Slang all generate adjoint kernels by source transformation and keep a light graph-level tape ([DiffTaichi](https://arxiv.org/pdf/1910.00935), [Warp docs](https://nvidia.github.io/warp/stable/user_guide/differentiability.html), [Slang guide](https://shader-slang.org/slang/user-guide/autodiff.html)). A VEX wrangle is one imperative kernel over columns, so this is the right model, and the plan owns the node graph, so it needs no runtime tape. JAX's recipe of JVP, partial evaluation, then transposition ([Autodidax](https://docs.jax.dev/en/latest/autodidax.html)) is a clean fit for a first-order SSA IR. `std::autodiff` is not on nightly as of January 2026 and differentiates host Rust, not runtime snippets ([Rust goals](https://goals.rust-lang.org/blog-post-2026-01.html)). Warp's documented failures translate into IR rules the plan lacks: columns must be write-once per kernel (versioned), because write-after-read yields wrong gradients; differentiable loops need static or declared bounds because Warp does not replay runtime-bounded loops in backward and Slang requires `MaxIters`; adjoints of gathers become scatter-adds, which are atomic on GPU and need a deterministic CPU fallback ([Futhark](https://arxiv.org/pdf/2202.10297)); and custom-derivative hooks are required for noise, SDF queries, raycasts and sorts. Differentiating through large data-dependent loops is unsolved in the notes, with three routes: bounded checkpointing, preallocated per-iteration scratch, or user-supplied or implicit-function-theorem adjoints for iterative solvers. Autodiff should run after simplification and before fusion, since Enzyme found differentiating optimized IR 4.2x faster ([Enzyme](https://par.nsf.gov/servlets/purl/10308799)). The plan's `Differentiability::{Smooth, Piecewise, None}` flag is compatible with Slang's `no_diff`; the research supports keeping the finite-difference gradient check strict because simulators can return wrong gradients ([DiffTaichi follow-up](https://arxiv.org/pdf/2207.05060)).

Two backend claims need tempering. Cranelift generates code about 10x faster than an LLVM system at roughly 14% slower output ([cranelift.dev](https://cranelift.dev/)), which suits interactive editing, but no 2025-26 source confirmed its wide-SIMD (AVX2/AVX-512) lowering. The notes' recommendation is a benchmark spike, with the OSL pattern as fallback: precompiled SIMD math and noise libraries called from JIT glue ([OSL overview](https://deepwiki.com/AcademySoftwareFoundation/OpenShadingLanguage)). The staged order should be a column-chunked SIMD interpreter with forward and reverse AD first, then fusion plus Cranelift in the background with an IR-hash kernel cache, then WGSL. Slider values must be runtime uniforms so edits never recompile. For GPU, wgpu is healthy (v30.0.1, 2026-08-21, [CHANGELOG](https://raw.githubusercontent.com/gfx-rs/wgpu/refs/heads/trunk/CHANGELOG.md)), but WGSL f64 and 64-bit atomics are unsourced, so the IR should treat f32 as the GPU type. Unreal PCG's experience, where GPU gains depend on grouping GPU nodes and minimizing CPU-GPU transfers ([Epic PCG GPU docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-with-gpu-processing-in-unreal-engine)), argues for GPU-resident fusion regions. Fusion barriers are cardinality-changing ops, neighbor gathers, global reductions and sparse-active-set changes; the plan's "fuse pointwise chains" claim is right but its scope should be stated that narrowly.

## Determinism is achievable per backend class, and the gate must say so

Content-addressing is well precedented. Bazel separates an action cache from a CAS ([Bazel](https://bazel.build/remote/caching)), Salsa backdates results so equal outputs stop downstream recomputation ([Salsa](https://salsa-rs.github.io/salsa/reference/algorithm.html)), and Nix's content-addressed derivations give the same early cutoff but remain experimental ([Nix manual](https://nix.dev/manual/nix/stable/store/derivation/outputs/content-address.html)). The plan should add early cutoff by output hash, which it does not mention, and use a two-level scheme: node-level action keys mapping to a Merkle manifest of fixed-size per-column chunk hashes (BLAKE3, [repo](https://github.com/BLAKE3-team/BLAKE3)), which falls out of the `Arc`'d column design. Bazel's key-hygiene lesson applies: every result-affecting input must be in the key (op implementation version, canonicalized params, imported file content hashes, WASM module hashes) and nothing else may leak in (thread count, wall clock, host paths).

Float determinism is the crux. Only +, -, *, /, sqrt and explicit `mul_add` are specified bit-exact; Rust documents `sin`, `cos`, `exp`, `powi` as non-deterministic across platforms, versions and even invocations, and NaN bit patterns are not portable ([Rust f32 docs](https://doc.rust-lang.org/std/primitive.f32.html), [RFC 3514](https://rust-lang.github.io/rfcs/3514-float-semantics.html)). Box2D and Rapier achieve cross-platform determinism only on tested compiler/architecture matrices, with custom trig, FMA contraction off and CI hash checks, and both call it fragile ([Box2D](https://box2d.org/posts/2024/08/determinism/), [Rapier](https://rapier.rs/docs/user_guides/rust/determinism/)). So the contract needs a pinned in-repo math crate with a lint banning std transcendentals in hashed paths, fixed-shape reduction trees over fixed-size blocks, total-order merges, Philox-style counter RNG keyed by stable element ids ([Random123](https://www.thesalmons.org/john/random123/releases/latest/docs/)), and NaN and -0 canonicalization at node boundaries. The rayon claim is an inference: reduction order depends on splitting, so it must be tested, not assumed. GPUs cannot match: float atomics are order-dependent ([PyTorch notes](https://pytorch.org/docs/1.5.1/notes/randomness.html)) and no source established WGSL accuracy or driver FMA behavior. A WASM reference backend with relaxed SIMD and threads off is a plausible portable oracle at a speed cost ([WASM nondeterminism](https://github.com/WebAssembly/design/blob/main/Nondeterminism.md)).

A shared cache also needs a trust model the plan lacks. CAS blobs verify themselves, but action-cache entries are claims, and anyone who can write them can poison others' builds ([Bazel](https://bazel.build/remote/caching), [Stripe](https://stripe.com/blog/fast-secure-builds-choose-two)). Because cooks are pure and deterministic, a sampling auditor can re-cook random hits on trusted workers and quarantine mismatching writers, a verification Bazel cannot cheaply do. Use per-principal write namespaces, authenticated transport and GC TTLs that exceed referenced blob lifetimes ([Buck2](https://buck2.build/docs/users/advanced/deferred_materialization/)).

## Agent-native is commoditizing, so depth must carry Bet 4

The dominant agent pattern is a thin execute-code-plus-screenshot bridge. Blender MCP has about 30k stars, an unauthenticated localhost socket, timeouts on complex requests, and a published code-injection CVE ([GitHub](https://github.com/ahujasid/blender-mcp), [CVE-2026-10688](https://www.sentinelone.com/vulnerability-database/cve-2026-10688/)). Houdini already has community MCP servers ([Glama](https://glama.ai/mcp/servers/bemmg7xfl7)) and an SideFX/NVIDIA Apex Script MCP preview ([Jon Peddie](https://www.jonpeddie.com/news/sidefx-and-nvidia-bring-mcp-powered-ai-agents-to-houdini-22s-rigging-workflow-at-siggraph-2026/)). Connectivity is therefore not an edge; the typed language, static checks, determinism and gym are. The research supports static feedback: 3DCodeBench found most failures are API mismatches, which a checker catches ([arXiv](https://arxiv.org/abs/2606.01057)), and type-aware constraining cut compile errors by more than half in other languages, though it needs model internals and does not apply to API-only models ([Mündler et al.](https://arxiv.org/abs/2504.09246)). The same paper cites 40-60% compile-error rates for sparse-data languages such as OCaml and Haskell, which is the cold-start risk for `hcs`. No study compares a DSL with Python for 3D agents, so "agents write 30 lines in `hcs`" is an untested hypothesis. The notes recommend a three-arm gym experiment (`hcs`, Python bindings, flat tools), a Rust/TypeScript-near surface, a generated reference, millisecond diagnostics with fixes, and grammar for constrained decoding. The token-economics case for code-style surfaces is real but modest in independent tests (input tokens -78.5%, output +120%, [AIMultiple](https://research.aimultiple.com/code-execution-with-mcp)). Anthropic's 98.7% figure is a single-workflow example ([Anthropic](https://www.anthropic.com/engineering/code-execution-with-mcp)). The plan's long fine-grained tool list should be exposed through search-and-describe tools with progressive disclosure; retrieval raised tool-selection accuracy from 13.6% to 43.1% in one test ([RAG-MCP](https://arxiv.org/html/2505.03275v1)).

Critics and gyms need calibration. The best VLM judge agreed with humans at 0.66 versus 0.79 human-human on BlenderGym; scaling inference helps, and the best generate-versus-verify budget split shifts with budget ([BlenderGym](https://arxiv.org/html/2504.01786v1)). VLMs track prompt adherence better than geometry, CLIP correlates weakly with human judgment (Pearson 0.074 on geometry), and verdicts need order-swapping for position bias ([DB-3DME](https://arxiv.org/pdf/2606.10142)). Hence specs stay the hard gate, VLM scores are shaping terms, and `critique` should use order-swapped pairwise judging and question-decomposed rubrics ([CADCodeVerify](https://arxiv.org/pdf/2410.05340)). The RL case is real only in analogues: CAD-Coder's GRPO with a Chamfer reward ([NeurIPS](https://proceedings.neurips.cc/paper_files/paper/2025/hash/564a224e88f2490f3c1deaae877d37e3-Abstract-Conference.html)) is the closest, and the deterministic runtime's cheap, noiseless rewards fit that pattern. No evidence shows RL improving end-to-end DCC editing. LLM layout placement fails with direct coordinates (collisions) and solver-based layouts miss semantics ([Holodeck](https://arxiv.org/pdf/2312.09067)), which supports a relations-in, instances-out placement node and default `grounded`/`connected` specs against floating parts.

## Inverse design works for fixed graphs, so Phase 3 to 6 gates need rewording

Gradient fitting of fixed procedural graphs is established: ADPM converts node graphs to differentiable graphs and returns multiple parameter configurations for under-determined edits ([Adobe](https://research.adobe.com/publication/automatic-differentiable-procedural-modeling)), and DiffMat v2 combines gradient and gradient-free mixed-integer search, matching the plan's hybrid solver ([CFG MIT](https://cfg.mit.edu/publications/diffmatv2)). DiffCSG assumes fixed discrete structure and fuzzy-logic booleans give a sourced relaxation ([arXiv 2409.01421](https://arxiv.org/pdf/2409.01421), [fuzzyBoolean](https://www.dgp.toronto.edu/~hsuehtil/pdf/fuzzyBoolean.pdf)). Learned inverse networks such as DI-PCG need per-generator training, about 30 GPU-hours ([arXiv 2412.15200](https://arxiv.org/abs/2412.15200)), so they belong in Phase 7. Simulation gradients are local tools: collisions can make gradients entirely wrong without exact time-of-impact ([DiffTaichi](https://cdnjs.deepai.org/publication/difftaichi-differentiable-programming-for-physical-simulation)), chaos can make exact gradients useless ([arXiv 2111.05803](https://arxiv.org/pdf/2111.05803)), and DiffCloth concedes self-collision gradients are unresolved ([arXiv 2106.05306](https://arxiv.org/pdf/2106.05306)). Differentiable fluids have no sourced evidence. Neural surrogates have no sourced support for "within 5% at 50x"; failure modes include poor generalization to new domains, and the hybrid pattern feeds network output into the physical solver ([CFDNet](https://arxiv.org/pdf/2005.04485)). Hydraulic erosion already runs interactively on GPU without learning ([Jako and Toth](https://diglib.eg.org/handle/10.2312/EG2011.short.057-060)), so smoke, not erosion, is the surrogate priority. On rendering, only Mitsuba's `llvm_ad` CPU variant is sourced, with no CPU timings ([Mitsuba](https://mitsuba.readthedocs.io/en/stable/src/inverse_rendering/gradient_based_opt.html)); visibility discontinuities need reparameterization or path replay ([Dr.Jit paper](https://arxiv.org/pdf/2202.01284)). Silhouette and SDF losses avoid that difficulty, supporting the soft-rasterizer-first order. Slang.D reports roughly 5x forward and 22x reverse overhead over primal on a GPU ([NVIDIA](https://research.nvidia.com/labs/rtr/publication/bangaru2023slangd)), a planning ratio for reverse-mode cost. Choosing CMA-ES over Bayesian optimization beyond roughly 15 parameters is supported by general black-box results ([arXiv 2303.00890](https://ar5iv.labs.arxiv.org/html/2303.00890)) but not by any procedural-graph benchmark.

## Licensing and clean-room: the EULA is the binding constraint

Copyright is the lesser risk. The US Supreme Court assumed API declaring code was copyrightable and still found fair use ([Jones Day](https://www.jonesday.com/en/insights/2021/04/supreme-court-google-wins-copyright-battle)), Lotus v. Borland held menu hierarchies are uncopyrightable methods of operation ([ruling](https://hallapproved.com/us/cases/ca1/1995/195952)), and the CJEU held functionality, programming languages and data formats unprotected ([Fieldfisher](https://www.fieldfisher.com/en/insights/sas-institute-inc-v-world-programming-limited)). Reusing functional node and parameter names is therefore likely defensible, though unsettled in the US. Copying documentation prose, examples, icons or help text is the exposure. Contract is the larger risk. SideFX's EULA forbids using the Software for competitive analysis, to build a competing product, or to copy its features or functions (s.4.2), and forbids converting non-commercial files to commercial formats (s.4.1(x)) ([EULA](https://www.sidefx.com/download/eula/)). Any contributor who runs Houdini to learn behavior risks breach regardless of copyright, so PLAN §3.6 ("observable Houdini behavior") and §8 need a rule: input is only published papers, third-party tutorials and public documentation, structured in a spec-writer and implementer split on the ReactOS model ([Linux.com](https://www.linux.com/?p=526307)). The ReactOS audit was never published and critics disputed its cleanliness, so provenance logs per module matter. Agents add exposure: system prompts and retrieval corpora must exclude SideFX documentation text.

Trademark: the HOUDINI word mark is registered ([Justia](https://trademarks.justia.com/746/83/houdini-74683775.html)) and the EULA bars use of SideFX names and logos without consent ([SideFX license](https://www.sidefx.com/legal/license-agreement)). The repo name, `HoudiniGym`, and native `.hip`/`.hda` extensions should change before any release; KineFX, Karma XPU and Solaris appear as claimed marks. Dependencies are favorable: OpenUSD (Apache-2.0 with a trademark clause change), OpenVDB 12+ (Apache-2.0), OpenSubdiv and Embree are compatible with an Apache-2.0 or MIT OR Apache-2.0 project ([OpenUSD](https://github.com/PixarAnimationStudios/OpenUSD/blob/dev/LICENSE.txt), [Phoronix](https://phoronix.com/news/ASF-OpenVDB-12.0)). Choose Apache-2.0 for the patent grant, DCO plus an `Assisted-by:` trailer, and `cargo-deny` in CI. The US Copyright Office says prompts alone do not confer authorship ([Copyright Office](https://copyright.gov/newsnet/2025/1060.html)), so agent-written recipes need human authorship to be protectable. Patents were not searched: a clean-room VDB-like tree, FLIP, pyro and WFC need a patent search, since the notes recall DreamWorks VDB filings unverified.

## Rust ecosystem: buy the periphery, own the kernel

Versions and licenses were read from crates.io on 2026-10-09. Adopt: `rmcp` 3.5.1 for MCP ([crates.io](https://crates.io/api/v1/crates/rmcp)), `glam`, `bytemuck`, `wide` (std::simd is still nightly-only, [tracking issue](https://github.com/rust-lang/rust/issues/86656)), `blake3`, `cranelift-jit` 0.136.x and `wasmtime` 49.x (pin; both release monthly with breaking bumps), `salsa` 0.28.5 (churny, 0.28.3 yanked), `chumsky` plus `logos` for `hcs` with error recovery, `egui`/`egui-snarl` behind a wrapper, `openusd` 0.7.0 (pure-Rust usda/usdc/usdz, pre-1.0, [GitHub](https://github.com/mxpv/openusd)), `gltf` and `exr`. Isolate `wgpu`/`naga` 30.x in one crate with exact pins. Write own: the columnar store (not `arrow`), noise (it must be fusable into the IR), sparse volumes (`vdb-rs` is read-only and stale), and the viewport (`rend3` is dead since 2022). Booleans have no mature answer: `boolmesh` 0.1.10 (MPL-2.0, created November 2025) is the pure-Rust candidate to wrap and fuzz, with `manifold-rs` (C++) as an oracle. The notes found no verified Rust option for Alembic, MaterialX or FBX (`fbxcel` is stale), and the Autodesk FBX SDK is proprietary. Nothing was build-tested on the Windows GNU toolchain; one `cargo check` spike across both Windows targets is needed, and rapier's `enhanced-determinism` still needs cross-target hashing.

## Evidence gaps the notes flag

Houdini's internal copy behavior is unverified. Gaffer, OpenVDB/NanoVDB, Substance, and Geometry Script were not covered. Cranelift's wide-SIMD status, WGSL numeric rules, driver FMA behavior and rayon reduction behavior are unsourced. No CPU timings exist for differentiable rendering or simulation, and 2025-26 differentiable-geometry literature was thin. No head-to-head DSL-vs-Python result, no RL result on end-to-end DCC editing, and no PCG-specific CMA-ES versus Bayesian optimization benchmark was found. Legal findings rest on law-firm summaries and the EULA sections read (4.1, 4.2, 13.12). The HOUDINI mark owner and status of other marks, patents, Alembic/MaterialX/OpenEXR licenses and non-US law are unconfirmed. Several crate versions come from a summarizing fetcher, and `redb` and `csgrs` returned conflicting values.

## Conclusion

Research moves the plan's center of gravity. The defensible moat is not "agent-native Houdini" or any single representation; it is the combination of a verifiable, typed, deterministic runtime and measured gates that competitors' thin bridges cannot match. That moat depends on keeping the determinism contract honest (a declared reference class, owned math, CI hashes) because gym rewards, shared caches and regression tests all inherit its credibility. A cheap early experiment would produce the most information: a one-week spike combining the Cranelift SIMD benchmark, a three-arm `hcs` versus Python versus tools gym run on T1 tasks, and a two-platform hash comparison. The legal posture should be settled before the kernel hardens, because the clean-room process shapes who may do the behavior-parity work the plan's quality bar assumes. Counsel review of the EULA, the final name and a patent search should precede any public release; none of this report is legal advice.
